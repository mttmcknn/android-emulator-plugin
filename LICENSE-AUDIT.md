# Release license audit

Audited on 2026-10-08 against the local checkout of `mttmcknn/android-emulator-plugin` and the upstream sources linked below. This is an engineering inventory and compliance review, not a legal guarantee. The project's existing Apache-2.0 license is retained; third-party code and artwork retain their own terms.

## Distribution scope

`scripts/build-plugin.mjs` copies `runtime/` into `plugins/android-emulator-plugin/runtime/` and synchronizes the plugin version. Codex installs the plugin directory, so notices must exist inside that directory. A repository/source archive is a different deliverable: it also contains the root README, screenshots, tests, and build scripts. The original checkout had no archive builder, dependency lockfile, npm dependencies, vendored `node_modules`, or checked-in host scrcpy/FFmpeg/SDL/ADB executable. Runtime JavaScript imports Node built-ins and local modules; the browser uses local JavaScript/CSS and system fonts.

The sole initially bundled executable payload is the Android scrcpy server. The plugin speaks its protocol through its own JavaScript client and uses browser WebCodecs. Android SDK tools are discovered from the user's SDK; optional FFmpeg/ffprobe are found on PATH. Node is taken from Codex or PATH. Those installations are not redistributed by the plugin.

Navigation is a separate case: `runtime/core/backends/navigation-dependencies.mjs` can download Minimap and Google's Android CLI into its managed cache, then run them. They are not in the plugin archive, but their acquisition and later runtime components are part of this audit. Existing user-installed overrides and PATH tools are distinguished from downloads made by the plugin.

## Managed Minimap: exact evidence and fixes

The dependency manifest pins three supported Minimap v0.2.1 assets. All were fetched read-only, and all verified against both the plugin manifest and GitHub's published asset digests. Each tar archive contains exactly one entry, `minimap`, with no license or third-party notice file:

|---|---|---|
| macOS arm64 | [minimap-aarch64-apple-darwin.tar.gz](https://github.com/mttmcknn/minimap/releases/download/v0.2.1/minimap-aarch64-apple-darwin.tar.gz) | `a6c1afb83d62edc7be0f28fbf2c35e06eb187a01c10230f61c943a53c7794de3` |
| macOS x64 | [minimap-x86_64-apple-darwin.tar.gz](https://github.com/mttmcknn/minimap/releases/download/v0.2.1/minimap-x86_64-apple-darwin.tar.gz) | `d905ca3ca5c9ec3c6b0a0659b99767cb63c846fe789e7a6998338fa65fb9a362` |
| Linux x64 | [minimap-x86_64-unknown-linux-gnu.tar.gz](https://github.com/mttmcknn/minimap/releases/download/v0.2.1/minimap-x86_64-unknown-linux-gnu.tar.gz) | `729e7d85bfbd7bb01eada29c13dbc4e7357e23a78928d04b82c0f09de4c42b97` |

Authoritative application sources are [tagged LICENSE](https://github.com/mttmcknn/minimap/blob/v0.2.1/LICENSE), [Cargo.toml](https://github.com/mttmcknn/minimap/blob/v0.2.1/Cargo.toml), [Cargo.lock](https://github.com/mttmcknn/minimap/blob/v0.2.1/Cargo.lock), [CLI manifest](https://github.com/mttmcknn/minimap/blob/v0.2.1/crates/minimap-cli/Cargo.toml), and [release recipe](https://github.com/mttmcknn/minimap/blob/v0.2.1/.github/workflows/release.yml). The first-party application is Apache-2.0. `cargo metadata`/`cargo tree --offline --locked --edges normal --target aarch64-apple-darwin` resolved the application graph without executing the application or fetching tools.

[MINIMAP-LICENSES.txt](runtime/core/vendor/MINIMAP-LICENSES.txt) contains original license and copyright texts for 35 normal application crates used on macOS, plus Linux-only `linux-raw-sys 0.12.1`. Each crate's exact published source archive was checked against its checksum in the tagged Cargo.lock before collecting its notices. The file gives every version, upstream SPDX expression, archive checksum, and original source URL. Identical license texts are deduplicated; all upstream alternatives are retained, rather than assigning new terms.

Most crates permit MIT or Apache-2.0. `deunicode 1.6.2` declares BSD-3-Clause; `generic-array 0.14.7`, `strsim 0.11.1` and `zmij 1.0.21` declare MIT; `memchr 2.8.0` permits Unlicense or MIT; `rustix 1.1.4` and Linux-only `linux-raw-sys 0.12.1` include Apache/LLVM exception alternatives as recorded in their original files. BSD-3-Clause expressly requires the copyright, conditions and disclaimer to accompany binary distributions. MIT also requires its copyright/permission notice. The original one-file archives omitted these materials; retaining only the binary did not supply them.

The plugin now ships the known notice collection and writes `LICENSES.txt` beside a newly installed or existing managed Minimap executable. User-installed override/PATH binaries are not rewritten. This fixes the known application-notice gap in the plugin's own managed acquisition. It does not repair the upstream release archive itself.

`clap_derive`, `serde_derive`, and their proc-macro helper dependencies are build-time tools, not separately executed runtime components. Upstream `assert_cmd`, `predicates`, their helpers, test support and CI actions are development-only; they are not listed as shipped runtime dependencies. Generated application code and first-party source remain under their applicable upstream licenses.

All three binary assets contain Rust source paths identifying commit `b940084d7eb6a299eb4bfeb8e34901bc051e7ac4`, whose [commit metadata](https://github.com/rust-lang/rust/commit/b940084d7eb6a299eb4bfeb8e34901bc051e7ac4) identifies Rust 1.99.0. The exact Rust [COPYRIGHT](https://github.com/rust-lang/rust/blob/b940084d7eb6a299eb4bfeb8e34901bc051e7ac4/COPYRIGHT), [MIT](https://github.com/rust-lang/rust/blob/b940084d7eb6a299eb4bfeb8e34901bc051e7ac4/LICENSE-MIT), and [Apache](https://github.com/rust-lang/rust/blob/b940084d7eb6a299eb4bfeb8e34901bc051e7ac4/LICENSE-APACHE) texts are included as supporting known notices. Rust COPYRIGHT explicitly directs readers to `COPYRIGHT-library.html` for the standard library's component inventory. The [standard-library manifest at that commit](https://github.com/rust-lang/rust/blob/b940084d7eb6a299eb4bfeb8e34901bc051e7ac4/library/std/Cargo.toml) has external dependencies beyond Minimap's application Cargo.lock. The official versioned `https://doc.rust-lang.org/1.99.0/COPYRIGHT-library.html` returned 404 during this audit. A matching standard-library/LLVM/compiler-builtins notice inventory and binary build record/SBOM remain necessary to establish this subset; generic Rust MIT/Apache files are not evidence that every linked component has those terms.

The macOS arm64 binary dynamically references system `libiconv` and `libSystem`; those OS libraries are not present in its archive. No OS runtime has been copied into the plugin. Platform-specific binary linkage beyond the inspected macOS asset still needs to be reconciled with the upstream build record before claiming complete binary clearance.

## Managed Android CLI: launcher, payload and terms

[Google's download page](https://developer.android.com/tools/agents/android-cli/download) supplies the plugin's direct launcher URL and an [official installer](https://dl.google.com/android/cli/latest/darwin_arm64/install.sh). That installer downloads `android`, then runs it for a first download. It was read, not run. The plugin independently performs a similar first launch while checking `--version`.

The macOS arm64 launcher fetched on 2026-10-08 is a roughly 3.5 MB Mach-O file, SHA-256 `52618946fb521fa08de5729181d12cb9190a5d6a2e8e869f71799808bc82792e`, exactly matching the plugin's pin. Static strings identify a second URL, [latest/darwin_arm64/android-cli](https://dl.google.com/android/cli/latest/darwin_arm64/android-cli), and launcher metadata `1.0.16500706`. The launcher cache path/version check does not constrain the second download to the launcher's SHA or to an immutable release. Thus the existing checksum pins the launcher, not the effective runtime.

The effective payload was separately downloaded without execution for static inspection: 89,565,808 bytes, SHA-256 `204aeb6f8ad5420176cbc2d9a9c57e8108cbf42c62a17146650eba5552880c22`. Its embedded `main.jar/METADATA` reports version `1.0.16500706`. Its embedded ZIP contains 168 entries including `main.jar`, `lib/libdownloader_jni.dylib`, and a JRE whose release metadata identifies Java 25.0.4. Existing JRE legal files include GPLv2, Classpath/assembly exceptions, and third-party notices. The JAR has Apache LICENSE/NOTICE material, Checker Framework MIT notice, Lucene notice material, and Android CLI interaction notices naming BoofCV, GeoRegression, DDogleg, EJML and Commons IO. Those embedded materials are preserved by taking the upstream binary intact. This observation does not establish a full, versioned dependency closure or a redistribution grant for the entire payload, launcher, and native components.

Static inspection of `com/android/cli/ui/Tos.class` found a terms message identifying the Android SDK License Agreement and linking [Google's terms](https://developer.android.com/studio/terms), plus a `tos_displayed` record. The terms require acceptance before use (section 2.1); use is itself assent (2.2). Section 3.4 restricts SDK redistribution, with section 3.5 preserving applicable open-source licenses. These terms cannot be replaced by this plugin's Apache license or treated as already accepted by future users. No CLI binary was launched, SDK component installed, agreement accepted, or `tos_displayed`/SDK-license state changed during this audit.

Before publishing the existing automatic-download path, resolve a user-controlled acceptance/use basis and the exact licensing/provenance of the effective runtime, or require a separately installed CLI under terms the user has handled. Merely adding a link or checking the launcher checksum does not establish those facts. Any future decision to bundle the CLI/JRE requires its own component notices, source/offer analysis where applicable, and redistribution review; this plugin currently ships none of them.

## Artwork and source-archive publication limits

Robot copyright attribution has been corrected in the release files. [Google's brand guidance](https://developer.android.com/distribute/marketing-tools/brand-guidelines), updated 2026-08-07, separately requires review of creatives referencing its marks and limits Android in application/product naming. The current display name `Android Emulators` and robot branding have no approval or naming-basis record in the checkout. Obtain owner review/documented authorization or change the branding before treating those questions as resolved; attribution alone does not confer trademark rights.

The README PNGs are not inside the plugin directory. Their source/marketing publication is still distinct from the plugin's code license: Google's [product-visual rules](https://partnermarketinghub.withgoogle.com/brands/google/branding-guidelines/how-to-show-googles-brand/) distinguish informational use from compatibility demonstrations and restrict recreation/modification of UI. The root README's example-data caption does not establish screenshot rights or wallpaper provenance. OpenAI/Codex UI and marks also have their own [brand rules](https://openai.com/brand/). Verify actual capture origins and the applicable permitted use, obtain permission where required, or replace/exclude unverified imagery from documentation deliverables. No images have been relicensed or assigned speculative third-party terms.

## Remaining publication blockers

1. The Android CLI managed installer launches a terms-bearing launcher/effective payload without an established user acceptance basis, and the effective payload is a moving, unpinned download with no complete component/grant record.
2. The known Minimap application notices are now present, but matching Rust standard-library/LLVM runtime notices and exact platform binary provenance/linkage remain unverified. The source Cargo.lock does not identify the precompiled Rust runtime closure.
3. Android product naming/mark/creative authorization remains unverified. Robot CC attribution does not resolve it.
4. Screenshot capture/artwork/marketing provenance remains unverified for repository/source archives, although plugin-only packaging excludes the PNGs.

No conflicting terms were identified in the audited initially packaged components after these notice fixes. That is not a claim that every later runtime component is permissive: the effective external Android CLI includes a GPLv2 JRE with exceptions, and its terms/components require the separate analysis above. The plugin's top-level license has not been changed, no third-party work was relicensed, and the end-to-end release is not cleared while the listed issues remain. No release was published, pushed, or sent to remote CI.
